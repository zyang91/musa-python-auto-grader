User guide

Assignments

The dataset decides what can be checked. Each assignment gives the grader a different situation, and the rubric is designed around it.

Assignment 1

The Donut Effect. No answer key, so each step is checked against the student's own data.

 Assignment 2

Exploratory Visualization. No data handed in, so the required elements are graded from saved outputs.

 Assignment 3

Evictions and the NDVI. One shared zip, so there is an answer key for the first time.

 Assignment 4

Street Networks & Scraping. Everything is downloaded or scraped live, so the notebook is never run.

 Assignment 5

Yelp Reviews & Census Income. Census downloads and an 8 GB dataset, so the notebook is never run and no data is opened.

Assignment 1: The Donut Effect#

rubrics/hw1.yamlassignments/hw1.pydata required

Students download their own Zillow ZHVI extract, and Zillow revises and extends that file every month. Row counts, ZIP counts and final percentages therefore differ legitimately between submissions, so the grader never compares against a stored answer. It asks whether each step in the instructions worked, and checks it against the student's own data:

InstructionHow it is checked
Load the dataA pandas import, a read_* call, a relative path, and a wide frame with many month columns
Trim to PhiladelphiaEvery ZIP in the subset is a Philadelphia ZIP, and City/State hold no other place
Melt to tidyRow count equals this student's own unique ZIPs × unique dates, with values in a column named ZHVI
Split Center CityThe two frames partition this student's own Philadelphia ZIP set, using the template's ZIP list
Percent increase functionCalled on a frame the grader builds, so the right answer is known whatever data was loaded. See Hidden tests.
Compare the two groupsBoth averages exist, are plausible, and point in the Donut Effect direction

The only fixed values in the rubric are the ones the assignment itself fixes: the Center City ZIP list printed in the student template, and the two comparison dates (2020-03-31 and 2022-03-31). A regression test confirms this: the same notebook graded against a shorter, smaller, rescaled ZHVI file still scores 100/100.

Assignment 2: Exploratory Visualization#

rubrics/hw2.yamlassignments/hw2.pyno data

Students pick their own dataset and hand in only the notebook. The grader has no copy of the data, so it cannot re-run anything: every submission dies at read_csv. The content of a chart was never checkable, and this assignment doesn't ask for it. It asks whether the student can produce the required elements. So the rubric splits the assignment in two.

Facts, graded automatically (70 points)#

An Altair chart compiles to a Vega-Lite specification, and that specification is stored in the notebook's own saved output. The grader reads mean/count/bin transformations, interval brushes and transform_filter() cross-filters out of the spec instead of guessing from the source text. That is how it tells apart the three things students most often confuse:

Student wroteVega-Lite saysVerdict
alt.selection_interval() + add_paramsparams: [{select: {type: interval}}]brush ✓
.interactive()the same, plus bind: "scales"pan/zoom, not a brush
alt.selection_point()select: {type: point}a selection, half credit
transform_filter("datum.x > 5")filter with no parama subset, not a transformation
transform_filter(brush) across hconcatfilter: {param: …} + two viewscross-filter ✓ extra credit

Judgement, graded by a person (30 points)#

The assignment grades the matplotlib chart on "colour choices and clarity" and asks for written reasoning under each chart. The quality of a picture and the substance of a paragraph can't be checked by a machine. Those items always come back as manual_review, whatever they score. Each carries a provisional score built from real signals (labelling and colour calls extracted from the source, word counts, the position of each markdown cell) plus the text itself. A TA confirms or adjusts a number instead of starting from a blank box.

The grader records, per chart, where the evidence came from. If an instructor does supply the dataset, a freshly executed chart replaces the saved one automatically and confidence rises from 0.85 to 0.95.

The extra-credit dashboard is worth 0 points in the rubric so that it never inflates the maximum. When it is found, the item is flagged with the suggested bonus. A manual override on it adds to the student's total without changing what they are graded out of.

Assignment 3: Evictions and the NDVI#

rubrics/hw3.yamlassignments/hw3.pydata optional

Assignment 3 hands out assignment3-data.zip, and everyone works from it. That one difference changes the whole design: for the first time the right answers exist, so the grader checks results rather than inferring intent.

Fact about the shipped dataValue
Philadelphia census tracts in PA-tracts.geojson384

Rows in the tidy eviction frame5,376
Evictions in that frame149,472
Median NDVI inside the city limits0.2025
Median NDVI in the suburbs0.3748
Street trees sampled / their median NDVI2,480 / 0.178

Every value was recomputed under the variations students legitimately produce (crop=True and crop=False, masked and filled arrays, sjoin(how="inner") and how="left") before it was written into the rubric. Where a step has two defensible answers, both are listed rather than one being called wrong. For example, the optional unstack(fill_value=0).stack() fill gives 5,535 groups instead of 4,000.

Because the answers are fixed, a matched expected value scores confidence 1.0. Grading combines two readings, the saved outputs and the re-run, so the data is optional:

The correct demo submission scores
With all five data files supplied99.5 / 100
With no data supplied at all99.5 / 100

Supply the data and 19 of the 22 items come back confirmed by both readings. Leave it out and the grade comes from the submitted notebook alone, at one confidence step lower (0.9 rather than 1.0).

Calibrated against a real class#

The rubric was run over a full class's submissions and checked against per-item aggregates only. No individual notebook was read to tune it. Every pattern that came back marked down when the work was right was fixed in the grader and reproduced in tests/ with a synthetic fixture:

Correct work the first version marked downWhat the grader now accepts
Year columns relabelled 2003..2016 after the melt"e-03", "2003" and 2003 name the same year, in widget keys, tidy-frame columns and chart frame lists
A trend chart whose x axis is those integer yearsThe bokeh decoder never reads an evenly stepped integer column as the plotted totals
A line with its points overlaid (Curve * Scatter)An Overlay is the trend chart, in the re-run and in the saved output. Map overlays are not
2.1.2 with no polygon area printedBoth NDVI medians in the saved output (0.2025 and 0.3748) prove the city and suburb polygons, since only the right polygons produce both
2.2.3 histogram and map in one plt.subplots(1, 2) cellThat cell counts as both figures
2.2.3 city limits drawn as a filled background layerCounts as the city outline

A chart with no recorded values also no longer crashes the feedback text. The calibration scripts themselves (hw*_aggregate.py, calibration/) are in .gitignore: even anonymised, they are written against real student results and stay off the repository.

Assignment 4: Street Networks & Scraping#

rubrics/hw4.yamlassignments/hw4.pyno datanever executed

Every step of Assignment 4 talks to a server that is not ours. Part 1 downloads the planning districts from ArcGIS Open Data and the street network from the OpenStreetMap Overpass API (osmnx), and Part 2 drives a browser through five pages of Craigslist with a sleep between each. Re-running a class of these notebooks would repeat every one of those requests once per student, which is exactly the load the assignment itself warns will get an IP banned.

So rubrics/hw4.yaml says execution: mode: never, and the service honours it in every execution mode, local included: no kernel, no notebook container, no browser, no data placement. See Execution. The grade comes from the file the student handed in, read two ways:

  • The code they wrote. Each code cell is matched to the template cell it was filled in from, and the template's own lines are set aside first. The driver.get(url) and pd.concat(...) inside the provided scraping loop, or a def format_price(price_string): return stub, earn nothing. Each step is a list of requirements in the rubric, one regex each, scoped to its Part, so a TA can widen one without touching Python.
  • The outputs their own run saved. The crash count, the scraping log (Processing page 3... Number of apartments = 120), the results table, the rendered histograms, the Folium map and the Altair spec, including the scraped rows the spec embeds.

The one thing that does run: three pure functions#

format_bedrooms, format_size and format_price turn "2br" into 2, and calling them is far better evidence than reading them. So they, and only they, are cut out of the notebook (grader.function_sandbox) and called with typical Craigslist strings in the Docker sandbox, under the same isolation flags as a notebook run, above all --network none:

  • only the top-level def of each named function is extracted. No other statement of the notebook goes anywhere, and the submission itself is not mounted into the container;
  • decorators and annotations are stripped, and a function whose default argument is not a plain literal is refused, because those run at definition time;
  • only imports of re, string, math, decimal, numpy and pandas go along. selenium, requests and osmnx do not;
  • the expected answers stay on the host. The container runs grader.function_runner, which is told what to call, not what should come back.

In local mode the functions are not called

The machine has a network, so item 2.5 gets a provisional score from the source and goes to a TA. The sidebar says so before the run.

Scraping has to be shown, not loaded#

A results table read back from a CSV proves nothing about a scraper. Item 2.6 wants the completed loop in the notebook and the log it printed when the student ran it, and the results table only counts when that log is there. A table loaded from a file is recorded as such and goes to a TA.

Reference values, loosely#

There is no reference solution, and the street network and the listings both change. The only numbers used are the template's own: about 3,750 crashes in Center City (3,000–4,500 accepted), 120 listings a page, and a price per square foot around 1.5. Each only raises confidence. A number far outside its range sends the item to a person; it never costs a point on its own. As everywhere, anything short of full marks reaches a person.

Assignment 5: Yelp Reviews & Census Income#

rubrics/hw5.yamlassignments/hw5.pyno datanever executed

Assignment 5 has Assignment 4's problem and one of its own. 1.1 queries the Census API through cenpy and 1.2 downloads TIGER tract boundaries through pygris, so a re-run would repeat both downloads once per student. And the restaurants come from the Yelp Dataset Challenge, 8 GB in full. The class gets a 400 KB Philadelphia extract (restaurants_philly.json.gz), but a notebook that reads the full dump instead would take minutes and run the grading machine out of memory, once per student.

So rubrics/hw5.yaml also says execution: mode: never. No kernel, no container, no data placement, and no data file is opened: not the extract, not the dump. The tests make pd.read_json, pd.read_csv and gpd.read_file raise an error during grading. HW5Grader reuses Assignment 4's machinery: the student's code, read against per-step regex requirements, and the outputs their own run saved.

  • Each step is graded on the code under its own heading. The template has a ### 1.x heading above each step, so a code cell is graded under the heading it sits beneath. Otherwise the merge written for 1.5 would also earn 1.2's merge. A step with no code under its heading earns nothing from code written elsewhere, and says so, so a TA can look.
  • The usual mistakes are named: latitude passed as x in points_from_xy (−2), the Census's negative placeholder (−666666666) left in, the tracts never merged with income.
  • A notebook that reads the full Yelp dump is named, not penalised. The result can be the same, so it costs nothing, but 1.3's feedback says so.
  • 1.6 wants the plot and the answer: a seaborn line plot of stars against income, rendered and labelled, and a written answer to the question, in a new markdown cell or typed into the template's own.

Reference values, loosely#

The template's "7,350 restaurants" (7,000–7,700 accepted) and Philadelphia's ~408 tracts (350–420) never cost a point: a count inside its range raises confidence, and one outside it sends the item to a person. A query for another county is not penalised, since the template allows it, but it is flagged, because every restaurant is in Philadelphia. As everywhere, anything short of full marks reaches a person.
